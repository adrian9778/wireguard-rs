# 第四层：平台 IO 与启动并发模型

> **版本**：0.1.4
> **源码基准**：当前源码
> **范围**：`src/main.rs` / `src/platform/*` / `src/util.rs` / `src/wireguard/queue.rs`（握手并行队列）

## 1. 设计意图

核心协议逻辑（`wireguard`）只依赖 `Tun` / `UDP` / `UAPI` / `Endpoint` 四个 trait，不关心 Linux 细节；具体实现放在 `src/platform/linux/`，单测用 `src/platform/dummy/`。`main.rs` 把二者装配成进程（platform/mod.rs 偏移：`+1 ~ +16`，Linux 下 `pub use linux as plt`）。

### 1.1 启动后并发拓扑（main.rs 派生线程）

```text
main 线程（配置/退出）
  ├─ tun 事件线程：status.event() → cfg.up/down   (main.rs +142~+162)
  ├─ UAPI 服务线程：loop connect → spawn uapi::handle   (main.rs +165~+180)
  └─ WireGuard::new 内部按 CPU 数派生：
        handshake_worker × N   (wireguard.rs +296)
        tun_worker × 1          (接收明文 IP)
        udp_worker × 1          (接收 UDP 密文)
      + 每个 peer 持 router::worker 收发作业线程
```

> 平台 trait 实现（linux/dummy）与 `WireGuard::new` 的线程派生细节见下文 §2~§6。

## 2. platform 抽象 trait

### 2.1 `Tun` / `PlatformTun`（`src/platform/tun.rs`）

- `Trait：Tun`（偏移：`+51`）：关联 `Writer`/`Reader`/`Error`。
- `Trait：Writer`（偏移：`+16`）：`write(&self, src:&[u8]) -> Result<(),E>`（写明文 IP 到虚拟网卡）。
- `Trait：Reader`（偏移：`+31`）：`read(&self, buf:&mut [u8], offset:usize) -> Result<usize,E>`（从网卡读 IP，`offset` 预留头部空间）。
- `Trait：Status`（偏移：`+8`）：`event(&mut self) -> Result<TunEvent, E>`（`TunEvent::Up(mtu)` / `Down`）。
- `Trait：PlatformTun`（偏移：`+58`）：`create(name) -> Result<(Vec<Reader>, Writer, Status), E>`。
- `Enum：TunEvent`（偏移：`+3`）：`Up(usize)` / `Down`。

### 2.2 `UDP` / `PlatformUDP`（`src/platform/udp.rs`）

- `Trait：UDP`（偏移：`+16`）：关联 `Endpoint`/`Writer`/`Reader`。
- `Trait：Reader<E>`（偏移：`+4`）：`read(&self, buf:&mut [u8]) -> Result<(usize, E), E>`（读出数据报与来源端点）。
- `Trait：Writer<E>`（偏移：`+10`）：`write(&self, buf:&[u8], dst:&mut E) -> Result<(),E>`。
- `Trait：Owner`（偏移：`+28`）：`get_port()` / `set_fwmark()`（绑定生命周期内持有 socket）。
- `Trait：PlatformUDP`（偏移：`+38`）：`bind(port) -> Result<(Vec<Reader>, Writer, Owner), E>`。

### 2.3 `UAPI` / `PlatformUAPI`（`src/platform/uapi.rs`）

- `Trait：PlatformUAPI`：关联 `Error`/`Bind`（UnixListener）；`bind(name) -> Result<Bind, E>`。
- `Trait：BindUAPI`（同文件）：`connect(&self) -> Result<Stream, E>`（accept 一个 UAPI 连接）。

### 2.4 `Endpoint`（`src/platform/endpoint.rs` 偏移：`+3`）

`from_address(SocketAddr)` / `into_address()` / `clear_src()`（sticky socket：清除源地址信息）。

## 3. main.rs —— 进程启动

### 3.1 函数：`main`

**源码**：`src/main.rs` 函数：`main`（偏移：`+55 ~ +185`）
**职责**：装配并启动整个 WireGuard 进程。
**执行流程**：
1. 解析参数：`--foreground`/`-f`、`--disable-drop-privileges`、设备名（缺失 → `exit(-1)`）偏移：`+57 ~ +83`。
2. `plt::UAPI::bind(name)` 建 UAPI 套接字（失败 `exit(-2)`）偏移：`+86`。
3. `plt::Tun::create(name)` 建 TUN（失败 `exit(-3)`），得 `(readers, writer, status)` 偏移：`+92`。
4. 降权 `util::drop_privileges()`（可选，失败 `exit(-4)`）偏移：`+98`。
5. 非前台则 `util::daemonize()`（失败 `exit(-5)`）偏移：`+109`。
6. `env_logger` 初始化 偏移：`+120`。
7. `WireGuard::<plt::Tun, plt::UDP>::new(writer)` 构建设备 偏移：`+131`。
8. `readers.pop()` 逐个 `wg.add_tun_reader(reader)` 偏移：`+134`。
9. `configuration::WireGuardConfig::new(wg.clone())` 包配置层 偏移：`+139`。
10. 启 TUN 事件线程：循环 `status.event()`，`Up(mtu)→cfg.up(mtu)`、`Down→cfg.down()`（偏移：`+142 ~ +162`）。
11. 启 UAPI 服务线程：`loop { uapi.connect() → thread::spawn(configuration::uapi::handle) }`（偏移：`+165 ~ +180`）。
12. `wg.wait()` 阻塞至所有 tun reader 关闭（偏移：`+183`）。
**并发模型**：主线程阻塞于 `wait()`；TUN 事件线程、UAPI accept 线程、每连接 UAPI 处理线程、以及设备内部的 tun/udp/handshake worker 线程并行运行。

## 4. wireguard/queue.rs —— 握手并行队列

**Struct：`ParallelQueue<T>`**（queue.rs 结构：`ParallelQueue`）：`Mutex<Option<Sender<T>>>`（crossbeam bounded）。
**函数：`new`**（偏移：`+15`）：创建 `bounded(capacity)` 通道，克隆 `queues` 个 receiver 给 worker。
**函数：`send`**（偏移：`+29`）：若 sender 存在则 `send(v)`（关闭后静默丢弃）。
**函数：`close`**（偏移：`+35`）：置 `None` 关闭通道（供 `router::DeviceHandle::Drop` 终止 handshake worker）。
**调用方**：`WireGuard::new`（创建并按 CPU 数起 `handshake_worker`，wireguard.rs 偏移：`+296`）。

## 5. linux/udp.rs —— Linux UDP 实现

### 5.1 类型

`FD(RawFd)`（`Drop` 关 fd，偏移：`+12`）；`LinuxUDPReader`（V4/V6 枚举）；`LinuxUDPWriter`（持有 `sock4/sock6` Arc<FD>）；`LinuxOwner`（port + socket）；`LinuxEndpoint`（V4/V6，含 `in_pktinfo`/`in6_pktinfo` 以支持 sticky source）。

### 5.2 `Endpoint` 实现（偏移：`+132`）

`from_address(SocketAddr)` 把标准地址转 `sockaddr_in`/`sockaddr_in6` + 空 pktinfo；`into_address()` 反向；`clear_src()` 清空 pktinfo（用于重绑源）。

### 5.3 函数：`bind`（PlatformUDP）

**源码**：linux/udp.rs 函数：`bind`（偏移：`+671 ~ +720`）
**职责**：同时绑定 IPv6 与 IPv4 UDP 套接字到同端口。
**执行流程**：
1. `bind6(port)` 优先（成功则 `port=new_port`）偏移：`+675 ~ +678`。
2. `bind4(port)`（与 v6 同端口）偏移：`+681`。
3. 两者皆失败 → 返回错误 偏移：`+687 ~ +690`。
4. 构造 `readers`（V6/V4 各一）、`writer`、`owner` 偏移：`+692 ~ +718`。
**辅助**：`bind4`（偏移：`+598`）/`bind6`（偏移：`+519`）：`socket`+`setsockopt`（REUSEADDR、PKTINFO）+`bind`+`getsockname` 取端口。

### 5.4 函数：`write4` / `write6`（出站）

**源码**：linux/udp.rs 函数：`write4`（偏移：`+385 ~ +448`）、`write6`（偏移：`+320 ~ +383`）
**职责**：用 `sendmsg` + `IP_PKTINFO`/`IPV6_PKTINFO` 控制消息携带源信息写出。
**关键分支**：`errno==EINVAL` 时清空 `msg_control` 与 `dst.info` 重试一次（清除 sticky source）偏移：`+427 ~ +440`。
**返回值**：`io::Result<()>`。

### 5.5 函数：`read4` / `read6`（入站）

**源码**：linux/udp.rs 函数：`read4`（偏移：`+254`）、`read6`（偏移：`+200`）
**职责**：`recvmsg` 收数据报，把来源地址与 pktinfo 存入 `LinuxEndpoint`（sticky source）。
**返回值**：`(usize, LinuxEndpoint)`。

## 6. linux/tun.rs —— Linux TUN 实现

### 6.1 常量

`TUNSETIFF=0x4004_54ca`、`CLONE_DEVICE_PATH=b"/dev/net/tun"`（linux/tun.rs 偏移：`+9`）。

### 6.2 函数：`create`（PlatformTun）

**源码**：linux/tun.rs 函数：`create`（偏移：`+322 ~ +356`）
**职责**：打开 `/dev/net/tun` 克隆设备，`ioctl(TUNSETIFF)` 建接口（`IFF_TUN|IFF_NO_PI`）。
**参数**：`name:&str`。
**返回值**：`(Vec<LinuxTunReader>, LinuxTunWriter, LinuxTunStatus)`（当前仅单 reader，TODO 多队列）。
**错误处理**：名过长 `InvalidTunDeviceName`；开克隆设备失败 `FailedToOpenCloneDevice`；ioctl 失败 `SetIFFIoctlFailed`。

### 6.3 `LinuxTunReader::read` / `LinuxTunWriter::write`（偏移：`+88`/`+109`）

- `read`：`libc::read(fd, buf[offset..], len-offset)`，负数 → `Closed`。
- `write`：`libc::write(fd, src)`，`-1` → `Closed`。

### 6.4 `LinuxTunStatus::event`（netlink）

**源码**：linux/tun.rs 函数：`event`（偏移：`+176 ~ +262`）
**职责**：读 netlink `RTM_NEWLINK` 事件，按 `ifi_index==self.index` 判 `IFF_UP` 出 `TunEvent::Up(mtu)` / `Down`。
**辅助**：`get_mtu`（偏移：`+132`，`SIOCGIFMTU` ioctl）、`get_ifindex`（偏移：`+117`，`if_nametoindex`）。
**设计意图**：使 `main.rs` 的 TUN 事件线程能感知接口 up/down 并驱动 `cfg.up/down`。

## 7. linux/uapi.rs —— UAPI 套接字

**函数：`bind`**（linux/uapi.rs 偏移：`+15 ~ +21`）：在 `/var/run/wireguard/<name>.sock` 建 `UnixListener`（先 `create_dir_all` + `remove_file` 避免残留）。
**impl `BindUAPI for UnixListener`**（偏移：`+23`）：`connect()` = `accept()` 一个连接流。

## 8. util.rs —— 守护进程与降权

### 8.1 函数：`daemonize`

**源码**：util.rs 函数：`daemonize`（偏移：`+40 ~ +51`）
**职责**：两次 `fork` + `setsid` 脱离控制终端成为后台进程。
**被调用**：`fork_and_exit`（偏移：`+31`，父子分流：子继续、父 `exit(0)`）。
**错误处理**：失败返回 `DaemonizeError`（Fork/SetSession/...）。

### 8.2 函数：`drop_privileges`

**源码**：util.rs 函数：`drop_privileges`（偏移：`+53 ~ +85`）
**职责**：切到 `nobody` 用户并 `chroot("/tmp")` / `chdir("/")` 降权。
**关键调用**：`getpwnam("nobody")` → `chroot`(root 时) → `umask(0)` → `chdir("/")` → `setgid` → `setuid`。
