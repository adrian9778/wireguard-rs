# 第二层：简单例子——真实全路径走读

> **场景**：对端发起一次 WireGuard 握手，本端（响应方）收到一条 Handshake Initiation UDP 报文，完整处理并回送 Response，同时把协商出的会话密钥注册到路由器，使后续传输报文可解密。
> **版本**：0.1.4
> **源码基准**：当前源码
> **前置条件**：本设备私钥已通过 UAPI `set private_key=...` 设置（`WireGuard::set_key` → `handshake::Device::set_sk`）；对端 public_key 已通过 UAPI `set public_key=...` 添加（`WireGuard::add_peer` → `handshake::Device::add`）。前置配置路径见 `07-配置与UAPI函数级解析.md`。

## 1. 为什么选这条路径

它同时贯穿 README 强调的**握手模块 ↔ 路由模块**核心分离：一条 UDP 密文进，一条 UDP 密文出，并把 `KeyPair` 从握手状态机交给路由器。整条链路可端到端追踪，且只走主成功路径，不含异常分支。

## 2. 入站报文（脱敏）

一条 `TYPE_INITIATION`（值 = `1`，见 `src/wireguard/handshake/messages.rs` Const：`TYPE_INITIATION`）UDP 数据报到达本端 UDP 监听端口。其零拷贝内存布局由 `src/wireguard/handshake/messages.rs` Struct：`Initiation` 定义：

```text
Initiation = NoiseInitiation + MacsFooter
┌────────────┬──────────┬─────────────┬──────────────────┬──────────────────┬─────────┬─────────┐
│ f_type u32 │ f_sender │ f_ephemeral │ f_static (32+16) │ f_timestamp(12+16)│ f_mac1  │ f_mac2  │
│ =1 LE      │ 4B       │ 32B 瞬态公钥│ AEAD(S_pub,H)    │ AEAD(ts,H)        │ 16B     │ 16B     │
└────────────┴──────────┴─────────────┴──────────────────┴──────────────────┴─────────┴─────────┘
  共 148 字节（MAX_HANDSHAKE_MSG_SIZE，messages.rs Const）
```

> 真实密钥值为 32 字节随机量，此处不杜撰。消息解析与序列化测试向量见 `src/wireguard/handshake/messages.rs` mod tests（函数 `message_initiate_identity`）。

## 3. 全路径调用链（含真实文件 / 函数 / 参数 / 返回值）

```text
[UDP socket] 入站 Initiation 数据报 (src: 远端地址)
   │
   ↓ src/wireguard/workers.rs  函数：udp_worker
   │   参数：(wg, reader=B::Reader)；内部 reader.read(&mut msg) → (size, src: B::Endpoint)
   │   偏移：+103 ~ +146
   │   动作：首 4 字节 LittleEndian 读到 1 → 走 TYPE_INITIATION 分支
   │         wg.pending.fetch_add(1)；wg.queue.send(HandshakeJob::Message(msg, src))
   │
   ↓ src/wireguard/queue.rs  类型：ParallelQueue  方法：send
   │   参数：(v = HandshakeJob::Message(..))；内部 crossbeam bounded 通道发送
   │
   ↓ src/wireguard/workers.rs  函数：handshake_worker
   │   参数：(wg, rx: Receiver<HandshakeJob<B::Endpoint>>)；for job in rx 循环
   │   偏移：+148 ~ +269；匹配 HandshakeJob::Message(msg, mut src) 偏移：+180
   │   动作：计算 under_load；device = wg.peers.read()；device.process(&mut OsRng, &msg, Some(src.into_address()))
   │
   ↓ src/wireguard/handshake/device.rs  函数：process
   │   签名：process<'a, R>(&'a self, rng:&mut R, msg:&[u8], src:Option<SocketAddr>)
   │         -> Result<Output<'a, O>, HandshakeError>
   │   其中 Output = (Option<&'a O>, Option<Vec<u8>>, Option<KeyPair>)  (types.rs Type：Output)
   │   偏移：+308 ~ +431；匹配 TYPE_INITIATION 分支 偏移：+330
   │   内部调用：
   │     ├─ Initiation::parse(msg)                       (messages.rs)
   │     ├─ keyst.macs.check_mac1(...)                   (macs.rs)
   │     ├─ noise::consume_initiation(self, keyst, ...)  (noise.rs 函数：consume_initiation)
   │     ├─ self.allocate(rng, &pk)                     (device.rs 函数：allocate)
   │     ├─ noise::create_response(...)                 (noise.rs 函数：create_response)
   │     └─ peer.macs.generate(...)                     (macs.rs)
   │   返回：(Some(&peer.opaque), Some(resp_bytes), Some(keys))
   │
   ↓ src/wireguard/handshake/noise.rs  函数：consume_initiation (+330 ~ +404)
   │   签名：consume_initiation<'a,O>(device:&'a Device<O>, keyst:&KeyState, msg:&NoiseInitiation)
   │         -> Result<(&'a Peer<O>, PublicKey, TemporaryState), HandshakeError>
   │   动作：跑 Noise_IKpsk2 的响应方解密半程，解出对端 static 公钥 pk，返回临时状态
   │
   ↓ src/wireguard/handshake/noise.rs  函数：create_response (+406 ~ +488)
   │   签名：create_response<R,O>(rng, peer, pk, local, state, msg:&mut NoiseResponse) -> Result<KeyPair, HandshakeError>
   │   动作：生成响应方瞬态密钥，派生 KeyPair（initiator=false）
   │
   ↓ 回到 handshake_worker  偏移：+192 ~ +245
   │   if let Some(resp) → wg.router.send_raw(&msg, &mut src)  把 Response 写回 UDP  (router/device.rs 函数：send_raw)
   │   if let Some(peer) → peer.set_endpoint(src)；peer.opaque().sent_handshake_response()  (timers)
   │   if let Some(kp)   → peer.add_keypair(kp)  (router/peer.rs 函数：add_keypair) → 释放旧 id：device.release(id)
   │
   ↓ src/wireguard/router/peer.rs  函数：add_keypair  偏移：+436 ~ +498
   │   参数：(new: KeyPair) -> Vec<u32>（需释放的 receiver id 列表）
   │   动作：因 kp.initiator=false，存 keys.next；向 device.recv 映射写入 DecryptionState{kp.recv.id}
   │
[UDP socket] 出站 Response 数据报 → 对端
[router]     recv 映射新增一条 DecryptionState（receiver id = kp.recv.id），后续入站传输报文可解密
```

## 4. 关键类型与返回值

| 符号 | 位置 | 含义 |
|---|---|---|
| `HandshakeJob::Message(Vec<u8>, E)` | `src/wireguard/workers.rs` Enum：`HandshakeJob` | 入站握手任务载体 |
| `Output<'a, O>` | `src/wireguard/handshake/types.rs` Type：`Output` | `(peer 引用, 待发响应字节, 会话密钥)` 三元组 |
| `KeyPair` | `src/wireguard/types.rs` Struct：`KeyPair` | `send`/`recv` 两把 32 字节密钥 + `id` + `birth` + `initiator` |
| `DecryptionState` | `src/wireguard/router/device.rs` Struct：`DecryptionState` | 按 receiver id 索引的解密状态（含 AntiReplay） |
| `router::PeerHandle` | `src/wireguard/router/peer.rs` Struct：`PeerHandle` | 路由侧对端句柄，`add_keypair` 在此注册密钥 |

## 5. 最终结果（脱敏）

- **网络侧**：向对端源地址回送一条 `TYPE_RESPONSE`（值 = `2`，`messages.rs` Const：`TYPE_RESPONSE`）UDP 数据报。
- **状态侧**：`handshake::Device` 已为本次握 allocates 一个本地 receiver id（经 `allocate`），该 id 经 `create_response` 写入 Response 的 `f_receiver`；本地 `router::Device::recv` 映射中按 `kp.recv.id` 登记 `DecryptionState`，使后续携带该 receiver id 的传输报文能被解密。
- **密钥侧**：`KeyPair.initiator == false`，故只进入 `keys.next`（待确认态），待对端发来首个传输报文（确认）后由 `router::receive::sequential_work` 调 `peer.confirm_key` 转正。

> 这条主成功路径在第三层逐跳拆解；握手/路由的具体函数实现在第四层（05、06）函数级解析。
